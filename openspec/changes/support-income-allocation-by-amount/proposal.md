# Proposal

## Why

Виджет «Накопления» позволяет задать долю дохода процентом, но не позволяет напрямую указать нужную сумму. Это затрудняет планирование фиксированных ежемесячных отчислений и смешанных планов.

## What Changes

- Для каждой категории одновременно доступны поля процента и денежной суммы; изменение одного поля пересчитывает другое.
- Каждая категория сохраняет основу последнего редактирования. Изменение дохода пересчитывает только производное значение.
- Денежные суммы задаются с точностью до копейки; вычисленные проценты отображаются максимум с двумя знаками после запятой без завершающих нулей.
- При нулевом доходе денежное распределение сохраняется, а процент отображается как `—`.
- Превышение дохода сохраняется и отображается предупреждением с точной величиной превышения и отрицательным остатком «Операции».
- Существующие категории сохраняют прежнее поведение и начинают с процентной основы.

## Capabilities

### New Capabilities

- `income-allocation`: задавать месячное распределение дохода процентами и суммами.

### Modified Capabilities

None.

## Impact

- Затрагивает редактор виджета «Накопления», тип данных категорий, авторизованное сохранение Server Actions, схему Drizzle и добавочную миграцию.
- Суммы и остаток требуют расчётов в копейках; UI остаётся клиентским и использует существующие TanStack Query mutations.
- В область задачи не входят реальные переводы, транзакции и фактические балансы накоплений.
