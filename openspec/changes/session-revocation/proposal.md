# Proposal

## Why

Проверка 2026-10-20 на Preview (T-064): Auth.js v5 работает с `session: { strategy: 'jwt' }`, а `jwt` callback ничего не проверяет в базе. «Выйти» только удаляет cookie в браузере: токен, сохранённый до выхода, остаётся действительным до истечения (30 дней) — повторно подставленный токен открыл дашборд 6 из 6 раз. Смена пароля (T-048) не завершает сессии на других устройствах.

Решения владельца 2026-10-20: делать сейчас; срок сессии остаётся 30 дней; смена пароля завершает все остальные устройства и сохраняет текущее. «Выйти» завершает только текущую сессию.

## What Changes

- Каждый токен при входе получает случайный `sid` и версию сессий пользователя `sv`.
- «Выйти» записывает `sid` в таблицу `revoked_session` до момента истечения токена; заодно удаляются строки с истёкшими токенами.
- Смена пароля на /account и сброс пароля по ссылке увеличивают `user.sessionVersion`; токены со старой версией перестают работать. Текущая сессия после смены на /account получает новую версию и остаётся.
- Node-часть Auth.js сверяет токен с базой одним запросом не чаще раза в 5 минут на токен; /account, смена пароля и /login сверяют сразу. Отозванный или устаревший токен даёт «нет сессии», дальше работает поток истёкшей сессии T-054.
- Перенаправление вошедшего пользователя с /login переезжает из edge middleware на страницу входа: только Node runtime отличает отозванную сессию от действующей.
- Миграция `drizzle/0019_session_revocation.sql`.

Вне рамок: «выйти на всех устройствах», список активных сессий, изменение срока сессии, переход на database sessions.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `account`: выход и смена пароля завершают сессии на сервере.

## Impact

Код: `src/shared/auth/*` (`session-revocation.ts`, `session-store.ts`, `index.ts`, `types.ts`), `src/shared/db/schema.ts`, `src/app/account/*`, `src/app/login/page.tsx`, `src/middleware.ts`, `src/shared/api/auth-actions.ts`. Новый e2e `e2e/session-revocation.spec.ts`. ADR 0004.

Риски: после выкладки все токены без `sid` (выданные до неё) не принимаются — каждому пользователю один раз нужно войти снова. Миграция 0019 должна попасть в production до merge.
