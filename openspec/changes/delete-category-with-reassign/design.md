# Design

## Decisions

- Перенос сопоставляет операции по тексту `expense.category` с фильтром `userId = текущий` и `sharedBudgetId IS NULL`: общие операции и операции других пользователей не меняются, даже при совпадении имени.
- Проверки владения и «не последняя категория» выполняются внутри транзакции по одному чтению категорий пользователя; одинаковые id отклоняются до транзакции.
- Правила `keyword_mapping` удаляются существующим `ON DELETE CASCADE` по `categoryId`; отдельного удаления нет.
- При нуле операций клиент всё равно передаёт цель по умолчанию: сервер переносит 0 строк, контракт действия один.
- Отдельного кэша анализа нет: «Анализ» вычисляется из запроса операций, поэтому достаточно инвалидировать `expenses`.
