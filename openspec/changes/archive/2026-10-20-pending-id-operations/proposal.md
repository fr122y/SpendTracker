# Proposal

## Why

Оптимистичная запись живёт с временным id `temp-…` (или с client id расхода, ещё не записанным в базу), пока сервер не ответит на создание. Операции над такой записью уходят на сервер раньше неё: удаление только что добавленного расхода ничего не удаляет и строка возвращается после перезагрузки; первый созданный карман выбирается по временному id, и `initializePocketMonthBudget` отвечает HTTP 500 `Pocket not found` (T-063, Preview 2026-10-20); клик по чипу кармана до сохранения оставляет выбранным мёртвый id. Те же 500 видны у расходов (T-044) и категорий (T-046).

Отдельно: отложенное удаление расхода (окно «Отменить» 5 с) при перезагрузке или закрытии вкладки отправляется server action из `pagehide`, а такой запрос браузер обрывает — удаление теряется.

Задача T-034, решения владельца 2026-10-15 и 2026-10-20.

## What Changes

- Общий клиентский механизм `src/shared/lib/pending-ids.ts`: создание регистрирует id записи как ожидающий, успех разрешает его в настоящий id, ошибка отклоняет. Каждая мутация, принимающая id записи или ссылку на запись (удаление, изменение, архив, бюджет кармана, операции кармана и проекта, правила, общие бюджеты), сначала дожидается настоящего id и выполняется с ним; запросы по временному id выключены. Если создание не удалось, ожидающие операции отбрасываются без своего toast и отката: запись откатывает само создание с одним toast.
- Защита сервера: действия, получившие id `temp-…`, не отвечают 500. Чтения возвращают пустой результат, удаления и архивирование ничего не делают, остальные записи ничего не меняют и возвращают «нечего менять» (`null` или статус `unsaved_record`).
- Надёжное отложенное удаление расхода: ожидающее удаление записывается в `localStorage`; при `pagehide` или скрытии вкладки оно отправляется `fetch(..., { keepalive: true })` в новый route handler `POST /api/expenses/flush-deletes`, который удаляет расходы текущего пользователя (идемпотентно, temp id и чужие id пропускаются, правила кармана, проекта и общего бюджета те же, что у `deleteExpense`). При следующей загрузке приложения неподтверждённые удаления, срок которых прошёл, отправляются повторно и до подтверждения скрыты. UX окна «Отменить» не меняется.
- Карманы: автовыбор никогда не берёт карман, который ещё сохраняется; новый карман становится выбранным, как только получает настоящий id; до этого его чип показан с пометкой «сохраняется…» и не нажимается.

Вне рамок: очистка данных `e2e/pockets.spec.ts` (T-063), миграции БД, изменение UX окна «Отменить».

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `form-submission`: операции над ещё не сохранённой записью выполняются после её сохранения.
- `expense-editing`: отложенное удаление доходит до сервера при перезагрузке и закрытии вкладки.
- `pockets`: правило автовыбора и состояние «сохраняется…» нового кармана.

## Impact

Код: `src/shared/lib/pending-ids.ts`, мутации шести сущностей (category, expense, keyword-mapping, pocket, project, shared-budget), server actions в `src/shared/api/`, новый route `src/app/api/expenses/flush-deletes/route.ts`, `src/entities/expense/model/pending-deletes.ts`, `src/widgets/pockets/ui/pockets-section.tsx`, `CreatePocketForm`. Новый API Route — архитектурное изменение: ADR `docs/decisions/0003-expense-delete-flush-route.md`, строка в `AGENTS.md`.

Риски: операция, ждущая создания, видна пользователю как выполненная, но уйдёт на сервер позже; при неудаче создания она молча отбрасывается вместе с записью. Route handler — новая точка входа с записью: проверка сессии, владения и ограничение размера тела.
