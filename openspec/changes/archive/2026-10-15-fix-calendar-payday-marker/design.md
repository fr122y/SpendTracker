# Design

## Context

`salaryDay` и `advanceDay` хранятся в `user_settings` как целые числа без ограничений. Единственный потребитель для вычислений — `getCalendarDays` в `widgets/calendar`; бюджетные периоды от этих дней не считаются.

## Decisions

- `getPaydayInMonth(day, year, month)` в `shared/lib/payday.ts` возвращает `min(day, daysInMonth)`. Календарь вызывает её для каждого из трёх месяцев сетки (предыдущий, текущий, следующий), чтобы флаг дня был верным и для соседних месяцев, хотя выделение показывается только в текущем.
- `isValidPaydayDay(value)` — целое 1–31. Её используют и редактор, и Server Action, поэтому клиент и сервер проверяют одно и то же. Сервер бросает ошибку; существующий optimistic rollback показывает тост отката.
- Редактор рендерится вне `<button>` (поле ввода внутри кнопки — невалидная разметка) как группа с подписью, полем, подсказкой и сообщением об ошибке (`role="alert"`, `aria-invalid`).

## Risks

- Уже сохранённые значения вне 1–31 (если есть) продолжают отображаться; при дне > числа дней маркер стоит на последнем дне, при дне < 1 маркера нет. Миграция не требуется.
