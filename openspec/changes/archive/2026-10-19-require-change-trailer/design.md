# Design

## Где проверяется что

| Уровень          | Где                                                                                               | Что                                                                                                         |
| ---------------- | ------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| Коммит, локально | Husky `commit-msg` → commitlint, правило `change-trailer`                                         | ровно одна строка `Change:`, формат, существование id в рабочем дереве, `none` только для разрешённых типов |
| Коммит, CI       | job `commitlint` (`pull_request`, checkout merge-коммита), `npx commitlint --from base --to head` | то же для каждого коммита Pull Request; ловит `--no-verify`                                                 |
| Pull Request     | job `change-trailer` (`pull_request_target`, скрипт из базы)                                      | каждая затронутая папка change названа точным id; ни один id не указывает на несуществующий change          |

## Решения

- Правило — локальный плагин commitlint, а не отдельный скрипт: один конфиг для хука и CI, один источник сообщений об ошибке. Плагин читает `openspec/changes/` относительно рабочего каталога commitlint (корень репозитория).
- Заголовок Pull Request проходит через тот же конфиг; правило пропускается только при `COMMITLINT_PR_TITLE=1`, который выставляет шаг проверки заголовка. Локальный обход через эту переменную ловит CI так же, как `--no-verify`.
- Merge, revert, `fixup!` и `squash!` пропускаются `defaultIgnores` commitlint; скрипт Pull Request пропускает те же коммиты (несколько родителей или префикс сообщения), чтобы правила не расходились.
- Squash-коммит на `main` склеивает сообщения всех коммитов Pull Request, поэтому в нём может быть несколько строк `Change:` (например, архив нескольких change). Он не проверяется: правило применяется к коммитам Pull Request, и каждый из них несёт ровно одну строку.
- Поиск коммитов change: `git log --grep '^Change: <id>$'`. `%(trailers)` не подходит: GitHub при squash добавляет `Co-authored-by` после строки `---------`, и trailer-блок оказывается не последним.
- Скрипт `change-trailer` сверяет id с базовым checkout плюс с папками change, которые затрагивает сам Pull Request (новый change появляется в базе только после слияния).
