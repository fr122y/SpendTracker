# Proposal

## Why

В месячной аналитике уже видны суммы по категориям, но нельзя перейти от суммы к расходам, из которых она сложилась. Это затрудняет проверку трат и поиск повторяющихся описаний внутри категории.

## What Changes

- Активация категории открывает адаптивное read-only окно с расходами этой категории за выбранный месяц и текущий scope аналитики.
- Расходы показываются по датам от новых к старым; фильтр по автоматически сгруппированным похожим описаниям обновляет список и его количество/сумму.
- Группировка и фильтрация работают поверх уже загруженных расходов. Исходные описания и суммы остаются без изменений.

## Acceptance Summary

- Активация категории открывает dialog с расходами того же месяца и scope; список read-only и сгруппирован по дням от новых к старым.
- Описания объединяются в проверяемые automatic groups; selectable chips позволяют выбрать одну или несколько групп.
- OR-фильтр применяется сразу; без выбранных групп виден весь base set. Количество и сумма показывают результат относительно исходной категории.
- Пустой base set и фильтр без совпадений отображаются по-разному.

## Scope Boundaries

**In scope:** drill-down текущей категории, месяца и scope; read-only дневной список; фильтр по автоматически сгруппированным описаниям и сводка найденных расходов.

**Out of scope:** изменение базовых итогов аналитики; редактирование/удаление расходов; новые Server Actions, API, таблицы, persistent alias catalog, AI или сетевые вызовы; семантическая поддержка произвольных синонимов.

## Dependencies and Risks

Используются существующий авторизованный `getExpenses` query, селектор месяца/scope и установленная зависимость Fuse.js; новых runtime dependencies нет. Похожесть строк может объединить семантически разные однословные названия, поэтому правила ограничивают очевидные false positives, а варианты группы остаются inspectable. Группировка выполняется на текущем уже загруженном наборе доступных расходов.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `spending-analysis`: добавить переход от категории к read-only расходам месяца и фильтрацию по автоматически сгруппированным описаниям.

## Impact

- Затрагивает `AnalysisDashboard`, его read-only detail dialog/list и клиентские селекторы в `shared/lib`; существующие API, схема БД и зависимости не меняются.
- Использует текущий `getExpenses` query и правило выбранного месяца/scope. Обрабатываются только доступные текущему пользователю расходы; project-linked расходы остаются в `personal`, как в базовой аналитике.
- Добавляются проверки для модального сценария, фильтрации и детерминированных групп описаний. Runtime AI и сетевые вызовы не добавляются.
