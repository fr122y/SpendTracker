# Proposal

## Why

В приложении есть единая выбранная дата dashboard, и владелец решил (2026-10-13), что она используется во всех случаях. Форма новой операции кармана в виджете «Карманы» показывает собственное поле «Дата»: оно подставляет дату dashboard, но позволяет выбрать другую. Из-за этого операция может оказаться не в том дне и даже не в том месяце, который пользователь видит на экране, а форма содержит лишнее поле.

## What Changes

- Форма «Добавить покупку» и «Перевести в расходы» в виджете «Карманы» больше не содержит поля даты.
- Новая покупка или перевод сохраняется на выбранную дату dashboard, действующую в момент сохранения.
- Критерии приёмки: в форме нет поля «Дата»; сохранённая операция имеет дату, равную выбранной дате dashboard; если дата dashboard изменена при открытой форме, используется новая дата.

Вне объёма:

- Редактирование существующих операций. Сейчас дата существующей операции кармана не редактируется нигде: карточка истории меняет только сумму. Это поведение не меняется.
- Форма обычного журнала расходов, Server Actions, схема базы данных.

Зависимости: нет. Параллельное изменение `add-pocket-purchase-to-expense-form` добавляет в `pockets` отдельное требование и не пересекается с этим по смыслу.

Риски: пользователь, которому нужна операция задним числом, должен сначала выбрать дату в dashboard; это и есть правило единой даты.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `pockets`: требование «Show and edit pocket history in the shared month context» — форма новой операции не даёт выбрать дату и сохраняет операцию на выбранную дату dashboard.

## Impact

- `src/features/manage-pockets/ui/pocket-operation-form.tsx` и его README.
- Тесты `src/features/manage-pockets/__tests__/PocketOperationForm.test.tsx`, `src/widgets/pockets/__tests__/pockets-section.test.tsx`, e2e `e2e/pockets.spec.ts`.
- Публичный API слайса (`PocketOperationForm` и его props) не меняется.
