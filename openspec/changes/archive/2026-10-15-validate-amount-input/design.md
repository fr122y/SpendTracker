# Design

## Context

`MathInput` разбирал простое число через `parseFloat`, который читает префикс строки (`1 500` → 1, `15 руб` → 15, `1e5` → 100000), а выражение — через `evaluateMathExpression`. Результат зажимался в `min`/`max`, так что `-100` становился 0. Формы проверяли сумму через `Number(amount)`, который для выражения даёт `NaN`, поэтому кнопка ждала blur. Enter вызывал `blur()`, и фокус уходил на `body`.

## Decisions

- Один чистый разбор `parseAmountInput(raw, { allowZero, max })` в `shared/lib/money-amount.ts` используют `MathInput` и формы. Сначала проверяется набор символов (цифры, пробельные символы, `.,+-*/()`), затем выражение вычисляется существующим парсером. Токенизатор `math-eval` теперь требует, чтобы весь числовой токен был одним числом (`1.2.3` — ошибка, а не 1.2).
- Пробел между цифрами считается разделителем тысяч: все пробельные символы удаляются. `1,5` — это 1.5, а не 15: запятая всегда десятичная.
- Больше двух знаков после запятой округляется до копеек, а не отклоняется: выражения вроде `100/3` естественно дают длинную дробь, и одно правило для числа и выражения проще. Округлённое значение показывается в поле после blur или Enter.
- Предел 100 000 000 ₽ — константа `MAX_MONEY_AMOUNT`; проверка после округления (`100000000.004` допустимо, `100000000.01` нет).
- `MathInput` показывает ошибку через существующий проп `error` у `Input` (с `role="alert"` и `aria-invalid`) после blur или Enter и прячет её при следующем вводе, чтобы не мигать ошибкой на незаконченном `500+`. Валидность кнопки форма считает сама по исходному тексту, так что активность кнопки следует за вводом без задержки.
- Enter: `preventDefault`, вычисление; при успехе `form.requestSubmit()`, если поле в форме, иначе `blur()` (встроенные редакторы суммы сохраняют по вычисленному значению). `requestSubmit` не учитывает `disabled` у кнопки, поэтому обработчики форм проверяют валидность сами. Отправка идёт через тот же `onSubmit` и `useSubmitLock`.
- Сервер проверяет `isValidMoneyAmount` из того же модуля. Тексты исключений не меняются (кроме нового для дохода и проекта): prod скрывает их, а форма уже показала свою ошибку.
- Форма операции кармана сбрасывает id операции по числовому значению суммы, а не по тексту, чтобы замена `500+50` на `550` после Enter не считалась новой операцией.

## Risks

- `MathInput` с `max` прежде зажимал значение; теперь он отклоняет его. Все текущие вызовы пересмотрены.
- Сообщение для нулевого недельного лимита стало общим «Сумма должна быть больше 0» вместо «Лимит должен быть больше 0».
