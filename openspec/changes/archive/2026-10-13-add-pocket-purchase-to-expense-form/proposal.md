# Proposal

## Why

Покупку из кармана сейчас можно записать только в виджете «Карманы». В журнале операций — основном месте ввода расходов — такого сценария нет, поэтому пользователь, уже открывший форму журнала, вынужден уходить в другой виджет ради одной записи.

## What Changes

- Добавить в форму журнала операций сценарий «Покупка из кармана» рядом с существующими сценариями.
- При выборе сценария показывать выбор кармана по образцу выбора проекта; остальные поля формы не меняются: описание, сумма, категория с подсказкой по ключевым словам и ручным выбором.
- Предлагать сценарий только при наличии хотя бы одного неархивированного кармана; архивированные карманы в выборе не показывать.
- Записывать операцию на общую выбранную дату приложения; отдельного поля даты в форме журнала нет.
- Не проверять остаток кармана: покупка сохраняется и при отрицательном остатке.
- Сохранять запись, неотличимую от покупки, добавленной в виджете «Карманы».

Критерии приёмки:

- При наличии активного кармана в списке сценариев журнала есть «Покупка из кармана»; без активных карманов пункта нет.
- После выбора сценария виден выбор кармана только с активными карманами. Единственный активный карман выбран заранее; при двух и более выбор пуст, и без выбранного кармана операция не добавляется.
- Сохранённая покупка появляется в журнале за выбранную дату и в истории покупок этого кармана за месяц выбранной даты, уменьшает его остаток, входит в общие расходы и расходы своей категории и не входит в личный недельный операционный расход.

Вне рамок:

- Перевод из кармана в расходы («Перевести в расходы») из журнала.
- Показ имени кармана на карточке операции журнала.
- Удаление поля даты из формы операции виджета «Карманы».
- Изменения серверной проверки, схемы данных и миграции.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `pockets`: добавляется требование о записи покупки из кармана через форму журнала операций.

## Impact

- `src/features/add-expense`: новый сценарий и выбор кармана в `ExpenseForm`, тесты и README слайса. Слайс начинает импортировать `@/entities/pocket` — допустимое по FSD направление `features -> entities`.
- `e2e/`: сценарий записи покупки из кармана через журнал.
- Серверная часть не меняется: `addExpense` уже принимает `pocketId` и проверяет владельца, архив кармана и категорию; покупка — это `operationType: 'expense'` с `pocketId`. Миграция не нужна, внешние зависимости не добавляются.
- Запись проходит существующий путь журнала с optimistic update, откатом и повторным чтением.

Риски:

- Карман может быть архивирован в другой вкладке, пока форма открыта: сервер отклонит запись, optimistic update откатится. Отдельной клиентской обработки не добавляем.
- Запись журнала должна совпасть по полям с записью виджета; расхождение проявится в расчётах остатка и недельного расхода — закрывается тестом на состав сохраняемой операции.
- Список карманов загружается асинхронно: до его загрузки сценарий не предлагается, что не блокирует остальные сценарии формы.
