# Proposal

## Why

Pull Request сейчас проверяется только job `commitlint`: формат коммитов, заголовок PR и `npm run spec:check`. Typecheck, lint и unit-тесты запускаются лишь локально, поэтому изменение с красной проверкой может попасть в `main`, а слияние в `main` автоматически выкатывается в production.

## What Changes

- Добавить workflow `.github/workflows/verify.yml` с одним job `verify`, который на каждом Pull Request и на каждом push в `main` выполняет отдельными шагами `npm ci`, `npm run typecheck`, `npm run lint` и `npm run test -- --ci --maxWorkers=2`.
- Ограничить workflow правами `contents: read`, таймаутом 15 минут и отменой устаревших запусков для того же ref.
- Привести в соответствие с фактом формулировки в `docs/engineering/agent-workflow.md` и в блоке `context` файла `openspec/config.yaml`: приложение проверяется в job `verify`, проверка OpenSpec остаётся в job `commitlint`.

Критерии приёмки: на Pull Request этого изменения завершаются обе проверки, `commitlint` и `verify`; при падении typecheck, lint или тестов красным становится шаг с названием соответствующего этапа.

Вне рамок: включение обязательной проверки `verify` и защита `main`, покрытие, e2e-тесты, детектор ослабления тестов, gitleaks в CI, README-бейдж, изменение существующих workflow, кода приложения и тестов.

Зависимости: существующие npm-скрипты `typecheck`, `lint`, `test` и `package-lock.json`; новых зависимостей и секретов нет.

Риски:

- Локальные unit-тесты могут неявно читать git-игнорируемый `.env.local` через `next/jest`; в CI его нет. Если `verify` упадёт по этой причине, секреты не добавляются и тесты не ослабляются — причина фиксируется и решается отдельной задачей.
- Имя проверки `verify` позже станет обязательным status check, поэтому переименование job после этого потребует синхронного изменения настроек репозитория.
- `npm ci` выполняется в обоих job, что увеличивает суммарное время CI на Pull Request.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

None. Наблюдаемое поведение приложения не меняется, поэтому изменение объявлено с `skip_specs: true` без spec delta.

## Impact

Затрагиваются только CI-конфигурация (`.github/workflows/verify.yml`) и две документационные формулировки. Код приложения, тесты, схема базы данных, зависимости, секреты и настройки репозитория не меняются. Документ `design.md` не создаётся: архитектурных решений изменение не содержит.
