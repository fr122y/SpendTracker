# Proposal

## Why

Удаление личной категории оставляло её расходы с именем удалённой категории: «Анализ» продолжал показывать её плитку, а подтверждение ничего не говорило о расходах (T-045). У операции категория хранится текстовой копией имени и эмодзи, а не внешним ключом, поэтому удаление строки категории расходы не меняет.

## What Changes

- Server Action `deleteCategoryWithReassign(categoryId, targetCategoryId)` в одной транзакции переносит личные операции пользователя (без общего бюджета, включая операции карманов и проектов) с именем удаляемой категории на имя и эмодзи целевой и удаляет категорию; правила автокатегоризации удаляются каскадом. Возвращает число перенесённых операций. Прежний `deleteCategory` удалён.
- Server Action `countCategoryExpenses(categoryId)` возвращает число операций, которые будут перенесены.
- Диалог удаления показывает число операций и выбор целевой категории (по умолчанию «Другое», иначе первая оставшаяся), предупреждает об удалении правил; при нуле операций — простое подтверждение. Удаление последней категории недоступно.
- После удаления обновляются кэши категорий, операций и правил; «Анализ» строится из операций и больше не показывает удалённую категорию.

Вне объёма: категории общих бюджетов; миграция схемы.

## Capabilities

### New Capabilities

- `categories`: удаление личной категории с переносом операций.
