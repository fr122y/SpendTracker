# Design

## Context

Месячный бюджет кармана хранится в `pocket_month_budget` и создаётся `initializePocketMonthBudget` при первом открытии месяца копированием последнего более раннего бюджета. Операции — строки `expense` с `pocketId` и `operationType` `expense` (покупка) или `pocket_transfer` (перевод). Клиент уже загружает все операции пользователя через `useExpenses`.

## Decisions

- История вычисляется при чтении, без хранимых данных и миграций (решение исполнителя в карточке T-039). Чистая функция `getPocketMonthHistory` в `shared/lib` принимает сохранённые бюджеты, операции, дату создания кармана и выбранный месяц.
- Бюджеты читает существующий owner-scoped Server Action `getPocketMonthBudgets` через `usePocketMonthBudgets`; новый Server Action не нужен. Операции берутся из кеша `useExpenses`, поэтому оптимистичные изменения операций сразу отражаются в истории, а изменение бюджета инвалидирует ключ `pocket-budgets/<id>`. Запрос бюджетов выполняется только при раскрытии истории. `initializePocketMonthBudget` для прошлых месяцев не вызывается.
- Первый месяц — самый ранний из месяца `createdAt` кармана (в локальном времени браузера, как и выбранная дата dashboard), сохранённых бюджетов и операций; так часовой пояс не теряет месяц с данными.
- Месяц без сохранённого бюджета получает бюджет предыдущего месяца истории, то есть последний сохранённый более ранний или 0 — то же правило, что и инициализация. Такой бюджет помечен «(перенесён)».
- Покупки и переводы одинаково уменьшают остаток; остаток между месяцами не переносится.
- Виджет показывает 12 месяцев и кнопку «Показать ещё».

## Risks

- Для старого кармана с большим числом операций вычисление проходит все операции пользователя один раз на рендер (мемоизировано); это тот же объём, что у существующей месячной сводки.
