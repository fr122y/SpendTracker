# Spec Delta

## MODIFIED Requirements

### Requirement: Show and edit pocket history in the shared month context

Виджет карманов MUST использовать только общий выбранный dashboard date для месяца и MUST NOT предоставлять собственный календарь или выбор месяца. Виджет MUST показывать для выбранного месяца бюджет, использованную сумму и остаток, а также отдельную разбивку покупок и переводов. Виджет MUST показывать, за какой месяц открыт (например, «Октябрь 2026»). Виджет MUST предоставлять историю кармана по месяцам: для каждого месяца от месяца создания кармана до выбранного месяца, от нового к старому, — бюджет, потраченную сумму (покупки и переводы) и остаток или перерасход с явной подписью «Остаток» или «Перерасход». Для месяца без сохранённого бюджета история MUST показывать бюджет по правилу инициализации: последний сохранённый более ранний бюджет или 0. История MUST вычисляться при чтении из сохранённых бюджетов и операций; просмотр истории MUST NOT создавать или изменять месячные бюджеты. Остаток MUST NOT переноситься между месяцами истории. История архивированного кармана MUST быть доступна только для просмотра. Активация разбивки MUST открывать историю соответствующего типа за этот месяц в одной карточке операции. Карточка MUST показывать комментарий, дату и категорию компактно; только сумма MUST редактироваться через явное действие. Для активного кармана пользователь MUST иметь возможность изменять месячный бюджет и суммы существующих покупок и переводов; эти изменения MUST пересчитывать месячные суммы и недельное покрытие. Интерфейс MUST предоставлять добавление покупки или перевода и создавать новый карман. Пользователь MUST иметь возможность удалить покупку или перевод активного кармана из истории через подтверждаемое действие; история архивированного кармана MUST быть доступна только для просмотра. Удаление MUST пересчитывать использованную сумму, остаток кармана и недельное покрытие, если удалён перевод. Форма новой операции MUST NOT содержать поле даты; новая операция MUST сохраняться с выбранной dashboard date, действующей в момент сохранения. Для покупки форма MUST использовать локальные keyword-based category suggestions обычного журнала: найденная категория показывается компактно, неизвестная подсказка открывает ручной выбор, а ручное переопределение сохраняется для будущего совпадающего описания.

#### Scenario: Follow the dashboard month

- **GIVEN** виджет карманов показан рядом с другими виджетами dashboard
- **WHEN** пользователь меняет дату через общий month picker dashboard
- **THEN** виджет показывает бюджеты и операции нового календарного месяца
- **AND** виджет не отображает свой отдельный выбор месяца или даты

#### Scenario: Open monthly history in one operation card

- **GIVEN** выбранный месяц содержит покупки и переводы кармана
- **WHEN** пользователь активирует одну из двух строк разбивки
- **THEN** открывается список только соответствующего типа операций за выбранный месяц, по одной карточке на операцию
- **AND** пользователь может изменить бюджет периода и сумму операции
- **AND** дата, комментарий и категория остаются видимыми без дополнительных редакторов
- **AND** сохранённые изменения пересчитывают used, remaining и недельное покрытие

#### Scenario: Add an operation on the selected date

- **GIVEN** активный карман открыт в виджете
- **WHEN** пользователь выбирает добавление покупки или перевода и заполняет обязательные поля
- **THEN** форма не показывает поле даты
- **AND** новая операция записывается с выбранной dashboard date
- **AND** если dashboard date изменена при открытой форме, операция записывается с новой датой
- **AND** покупка требует категорию, а перевод не требует категорию

#### Scenario: Delete an operation from pocket history

- **GIVEN** выбранный месяц содержит покупку или перевод активного кармана
- **WHEN** пользователь выбирает удаление и подтверждает его
- **THEN** операция исчезает из помесячной истории
- **AND** использованная сумма и остаток кармана пересчитываются
- **AND** недельное покрытие пересчитывается, если удалён перевод
- **AND** отмена подтверждения сохраняет операцию

#### Scenario: Suggest or manually override a purchase category

- **GIVEN** пользователь вводит описание новой покупки из кармана
- **WHEN** описание совпадает с сохранённым keyword mapping
- **THEN** категория показывается как выбранная подсказка без постоянно открытого списка
- **AND** пользователь может явно открыть ручной выбор и заменить подсказку
- **AND** если совпадения нет, ручной выбор категории становится доступен
- **AND** ручной выбор сохраняется как keyword mapping для будущих описаний

#### Scenario: Show the displayed month

- **GIVEN** dashboard date находится в октябре 2026
- **WHEN** пользователь открывает карман
- **THEN** виджет показывает подпись «Октябрь 2026»
- **AND** разбивка покупок озаглавлена «Покупки за октябрь»

#### Scenario: Show remainder or overspend per month

- **GIVEN** карман создан в ноябре 2025, бюджет ноября сохранён как 400 ₽, за декабрь бюджет не сохранён и есть покупка на 100 ₽, а бюджет января 2026 равен 1 000 ₽ при покупках и переводах на 1 500 ₽
- **WHEN** пользователь при выбранном январе 2026 раскрывает историю по месяцам
- **THEN** первым показан январь 2026 с перерасходом 500 ₽, затем декабрь 2025 с бюджетом 400 ₽ и остатком 300 ₽, затем ноябрь 2025 с остатком 400 ₽
- **AND** для декабря не создаётся сохранённый месячный бюджет
- **AND** остаток ноября не добавляется к декабрю

#### Scenario: Limit a long history

- **GIVEN** история кармана содержит больше 12 месяцев
- **WHEN** пользователь раскрывает историю
- **THEN** видны 12 последних месяцев и действие «Показать ещё», которое показывает следующие месяцы
