# Design

## Context

Формы проверяли «уже отправляется» по состоянию React (`isPending`, `isSubmitting`). Повторное событие отправки, пришедшее до следующего рендера, видит старое значение, а формы с `await` перед мутацией (сохранение keyword mapping) пропускают все клики, пока ждут. Сервер создавал карман без проверки имени и присваивал каждому расходу новый `crypto.randomUUID()`, так что повтор запроса всегда давал новую строку.

## Decisions

- `useSubmitLock` в `shared/lib` держит флаг в `useRef` и сбрасывает его, когда задача отправки завершилась (успешно или с ошибкой). Формы, где мутация вызывается через `mutate`, переведены на `mutateAsync`, когда иначе замок отпускается до ответа (общие категории). Для синхронных обработчиков (проект, личная категория) замок закрывает вызов до перерисовки, после которой форма уже очищена.
- Уникальность имени проверяет сервер. `createPocket`, `renamePocket` и `restorePocket` открывают транзакцию, берут `SELECT ... FOR UPDATE` строки пользователя, читают активные карманы и только затем пишут. Конкурентные вызовы одного пользователя выстраиваются в очередь, и второй видит имя, записанное первым. Блокировка строки пользователя выбрана вместо advisory lock, чтобы остаться в API Drizzle, как `initializePocketMonthBudget`. Оставшийся риск — запись в обход этих действий; его закроет частичный уникальный индекс (T-058).
- Конфликт возвращается как `{ status: 'name_conflict', conflictingName }`, а не исключением: production-сборка Next.js скрывает текст ошибок Server Actions. Хуки превращают его в `PocketNameConflictError`, откатывают оптимистичное обновление без общего toast, формы показывают «Карман с таким названием уже есть». Формы также проверяют имя по уже загруженному списку, чтобы не делать заведомо отклоняемый запрос.
- Сравнение имён (`trim` + `toLocaleLowerCase('ru-RU')`) вынесено в `shared/lib/pocket-name.ts` и используется сервером, формами и восстановлением из T-038.
- Idempotency расхода без новых колонок: клиент передаёт UUID, сервер использует его как первичный ключ. Перед вставкой сервер ищет строку с этим id: своя строка — успех без второй записи и без повторной проверки наличных проекта; чужая — ошибка. Вставка идёт с `ON CONFLICT (id) DO NOTHING`, так что одновременный дубль тоже не создаёт вторую строку. Не-UUID отклоняется. Журнал создаёт id на каждую отправку (форма очищается сразу); форма операции кармана хранит id между повторами после сбоя и сбрасывает его при изменении полей.
- Распределение дохода: новая строка помечается как черновик в `useRef`; черновики не попадают в `updateBuckets`, пока у строки нет имени, и сохраняются при потере фокуса поля имени. Повторный клик «Добавить категорию» при уже открытой безымянной строке ничего не добавляет. Синхронизация с сервером сохраняет локальные черновики в конце списка.

## Risks

- Проценты, введённые в безымянную строку, не сохраняются до ввода имени.
- Повтор с тем же id и изменёнными данными вернёт успех по уже сохранённой операции; форма кармана сбрасывает id при изменении полей, чтобы этого не происходило.
