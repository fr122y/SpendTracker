# Proposal

## Why

Пользователь может распределять доход по накоплениям, но не может задать именованные карманы с отдельными бюджетами на каждый месяц, видеть фактические покупки и переводить деньги из кармана в недельные операционные расходы. Новый виджет свяжет план и историю, сохраняя выбранный месяц dashboard как общий временной контекст.

## What Changes

- Добавить отдельный виджет «Карманы» с постоянными пользовательскими карманами, бюджетом выбранного месяца, суммой использованных средств и остатком.
- Разделить операции кармана на покупку и перевод. Покупка остаётся обычным расходом для общей аналитики; перевод исключён из расходных итогов и покрывает перерасход личного недельного бюджета в неделю перевода.
- Хранить месячные бюджеты независимо: при первом запросе периода скопировать последнее сохранённое значение из более раннего периода, а при отсутствии предыдущего значения создать бюджет с нулевой суммой. Не переносить неизрасходованный остаток.
- Добавить создание, переименование и архивирование карманов, ввод покупок и переводов, редактируемую помесячную историю и сохранение истории архива.
- Использовать месяц и год общего `selectedDate`; виджет не добавляет календарь или отдельный выбор даты.

## Capabilities

### New Capabilities

- `pockets`: пользовательские карманы, независимые месячные бюджеты, операции и dashboard-поведение.

### Modified Capabilities

None.

## Impact

Потребуются новая capability spec, Drizzle-схема и migration-файл, авторизованные Server Actions, клиентские queries/mutations, доменные селекторы и UI в существующих FSD-слоях, регистрация виджета и обновление адаптации личного weekly-budget coverage. Покупки карманов остаются `expense` для spending analysis; weekly operational spend исключает их подобно project expenses. Переводы используют отдельный тип операции и не входят в expense analytics. Изменения не добавляют внешние зависимости и не требуют применения migration к реальной базе в рамках этой задачи.
