# Proposal

## Why

Добавление нового Playwright spec в `.github/e2e-specs.txt` сейчас требует обхода ruleset владельцем, хотя такое добавление только усиливает проверку `e2e`. Ослабить её можно лишь удалением или правкой строк, и именно это должно оставаться за владельцем.

## What Changes

- Правило, утверждённое владельцем 2026-10-20: `protected-paths` пропускает Pull Request, у которого единственный затронутый защищённый путь — `.github/e2e-specs.txt` со статусом `modified`, если head только добавляет строки (строки базы сохраняются по порядку), и каждая добавленная строка пустая, `#` комментарий или путь `e2e/<name>.spec.ts`, которого ещё нет в списке и который существует в дереве head.
- Удаление, правка или перестановка строки, переименование или удаление файла, лишние пути и дубликаты, а также любой другой защищённый путь в том же Pull Request падают как раньше, с причиной в колонке правила.
- Скрипт по-прежнему работает через `pull_request_target` из базовой ветки и читает базовую и head версии списка и добавленные spec через REST API; код Pull Request не выгружается. Неполные данные API по-прежнему ведут к fail-closed.
- Документация: заголовок `.github/e2e-specs.txt`, `docs/engineering/protected-operations.md`.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

None. Поведение приложения не меняется, поэтому изменение объявлено с `skip_specs: true`.

## Impact

`.github/scripts/protected-paths.mjs` и тесты. Pull Request меняет защищённые пути, поэтому `protected-paths` на нём красный по замыслу (его судит базовая версия скрипта); сливает владелец через обход ruleset.
