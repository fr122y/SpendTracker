# Design

## Context

Правила (`keyword_mapping` — личные, `shared_budget_keyword_mapping` — общие) уникальны по фразе в пределах пользователя или бюджета и ссылаются на id категории. Дефолтные правила создаются при регистрации (`seed-defaults`) и бэкфиллом; они остаются `fuzzy`.

## Decisions

- **Тип совпадения хранится в правиле.** `DEFAULT 'fuzzy'` — метаданные в PostgreSQL 11+, без перезаписи таблицы; CHECK добавлен `NOT VALID`, как в 0017.
- **Ручной выбор → `exact`.** Server Actions `saveKeywordMapping` и `saveSharedKeywordMapping` принимают `matchType` с умолчанием `exact`: все их вызовы — ручной выбор. Upsert по фразе заменяет и категорию, и тип: если фраза раньше была `fuzzy`-правилом, она становится `exact`.
- **Нормализация фразы** общая для правил и описаний (`normalizeKeywordPhrase`): trim, нижний регистр, схлопывание пробелов.
- **Без Fuse в матчере.** Сравнение идёт по целым словам (`\p{L}\p{N}`-токены): точная последовательность слов, затем общая основа после отбрасывания одного известного русского окончания (`а`, `ов`, `ами`, `ого` и т. п.; основа не короче 3 букв, «кафе» ≠ «кафедра»), затем расстояние Левенштейна 1 (слова 4–5 букв) или 2 (от 6 букв). Слова короче 4 букв совпадают только точно. Приоритет: ранг совпадения, затем длина ключевого слова, затем позиция в описании.
- **Правка расхода.** Диалог T-044 при смене категории личного расхода сохраняет `exact`-правило для итогового описания; ошибка правила откатывается своей мутацией и не мешает правке расхода.
- **UI правил.** Список правил категории строится из уже загруженного списка правил пользователя или бюджета; удаление оптимистичное.

## Risks

- Preview и production читают `matchType`: до миграции запросы правил падают. DEV — сразу после push; production — `DB Migration` до слияния.
- Старые испорченные `fuzzy`-правила (целые фразы) теперь совпадают только если все их слова есть в описании целыми словами; их нужно удалить вручную через новый список.
