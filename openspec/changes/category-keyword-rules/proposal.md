# Proposal

## Why

Подсказка категории по описанию непредсказуема (T-047): fuzzy-поиск Fuse находит ключевое слово внутри чужого слова («тест» ≈ «ресторан» → «Еда»), а точное совпадение дальше по тексту проигрывает первому похожему слову. Ручная смена категории сохраняет всё описание как обычное нечёткое правило, и после этого несвязанные описания получают эту категорию. Правила нигде не видны и не удаляются.

## What Changes

- Миграция `0018_keyword_match_type.sql`: колонка `matchType` (`exact` | `fuzzy`, `NOT NULL DEFAULT 'fuzzy'`) у `keyword_mapping` и `shared_budget_keyword_mapping` и CHECK `NOT VALID`. Существующие правила остаются `fuzzy` и работают как раньше по смыслу.
- Ручной выбор категории (форма добавления расхода, карманы, проекты, общий бюджет) и смена категории в диалоге правки расхода (T-044) сохраняют правило `exact`: вся фраза описания, нормализованная (trim, нижний регистр, схлопнутые пробелы) → выбранная категория. Правило с той же фразой заменяется.
- Новый матчер: сначала `exact`-правило, равное всей фразе; затем `fuzzy`-правило, слова которого стоят в описании целыми словами (длиннее — лучше, затем раньше); затем однословное `fuzzy`-правило с окончанием (до 3 букв) или опечаткой (1–2 правки) у целого слова. Подстрока внутри другого слова не совпадает.
- `saveKeywordMapping` проверяет, что категория принадлежит пользователю. Новый Server Action `deleteSharedKeywordMapping` с проверкой участия в бюджете.
- Настройки категорий: у каждой личной и общей категории раскрывающийся список её правил с типом совпадения и кнопкой удаления.

Вне объёма: подпись подсказки при смене описания без blur (T-047, #7) и чистка испорченных правил production-аккаунта (делается вручную через новый UI).
