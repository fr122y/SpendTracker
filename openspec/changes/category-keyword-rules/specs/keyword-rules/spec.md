## ADDED Requirements

### Requirement: Keyword rule match type

Каждое правило автокатегоризации, личное и общего бюджета, MUST иметь тип совпадения `exact` или `fuzzy`. Существующие правила и правила по умолчанию MUST иметь тип `fuzzy`. Фраза правила и описание расхода MUST нормализоваться одинаково: обрезка пробелов по краям, нижний регистр, несколько пробелов подряд заменяются одним.

#### Scenario: Existing rules keep fuzzy matching

- **GIVEN** правило было создано до появления типа совпадения
- **THEN** оно имеет тип `fuzzy`

### Requirement: Manual category choice saves an exact phrase rule

Когда пользователь вручную выбирает категорию расхода — при добавлении личного расхода, покупки из кармана, проектного расхода, общего расхода или при смене категории в диалоге правки личного расхода — приложение MUST сохранить правило `exact` для всей нормализованной фразы описания и выбранной категории. Правило с той же фразой MUST заменяться. Правило `exact` MUST NOT влиять на подсказку для других описаний. Сервер MUST отклонять правило для категории, которая не принадлежит пользователю или бюджету.

#### Scenario: Manual choice is remembered for the same phrase

- **GIVEN** пользователь выбрал категорию «Тесты» для описания «Тест расход»
- **WHEN** он вводит описание « тест расход »
- **THEN** подсказана категория «Тесты»

#### Scenario: Manual choice does not affect other descriptions

- **GIVEN** есть правило `exact` «тест расход» → «Тесты»
- **WHEN** пользователь вводит «тест» или «тест расход большой»
- **THEN** это правило не используется

#### Scenario: Change category in the edit dialog

- **WHEN** пользователь меняет категорию личного расхода «Кофе с собой» на «Кафе» в диалоге правки
- **THEN** сохраняется правило `exact` «кофе с собой» → «Кафе»

### Requirement: Rule matching order

Подсказка категории MUST выбирать правило в порядке: правило `exact`, равное всей нормализованной фразе; правило `fuzzy`, все слова которого стоят в описании целыми словами подряд; однословное правило `fuzzy`, совпадающее с целым словом описания с окончанием до трёх букв или с небольшой опечаткой. Ключевое слово MUST NOT совпадать с частью другого слова. При равном типе совпадения MUST выигрывать более длинное ключевое слово, затем более раннее в описании.

#### Scenario: No substring false positive

- **GIVEN** есть правило `fuzzy` «ресторан» → «Еда»
- **WHEN** пользователь вводит «ТЕСТ покупка»
- **THEN** категория не подсказана

#### Scenario: Exact rule beats fuzzy

- **GIVEN** есть правило `fuzzy` «молоко» → «Продукты» и правило `exact` «молоко для кофе» → «Кафе»
- **WHEN** пользователь вводит «молоко для кофе»
- **THEN** подсказана категория «Кафе»

#### Scenario: Whole word beats an earlier typo

- **GIVEN** есть правила `fuzzy` «ресторан» и «такси»
- **WHEN** пользователь вводит «ресторн такси»
- **THEN** подсказана категория правила «такси»

### Requirement: Rules list in category settings

Настройки категорий MUST показывать у каждой личной категории и категории общего бюджета список её правил с фразой и типом совпадения. Каждое правило MUST удаляться отдельной кнопкой; удаление общего правила MUST проверять участие пользователя в бюджете.

#### Scenario: Delete a rule

- **GIVEN** у категории «Еда» есть правило «ресторан»
- **WHEN** пользователь открывает правила категории и удаляет его
- **THEN** правило исчезает из списка и больше не подсказывает категорию
