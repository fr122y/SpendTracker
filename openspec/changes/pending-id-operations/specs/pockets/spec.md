# Spec Delta

## MODIFIED Requirements

### Requirement: Manage personal pockets and preserve archived history

Система MUST предоставлять каждому пользователю отдельный список постоянных именованных карманов. Пользователь MUST иметь возможность создать карман, изменить его имя, архивировать его и восстановить архивированный карман. Архивирование MUST сохранять имя, бюджеты и операции только для просмотра: для архивированного кармана система MUST отклонять изменение месячного бюджета, создание месячных бюджетов, добавление покупок и переводов, изменение и удаление существующих операций, в том числе при прямом вызове серверного действия. Восстановление MUST возвращать карман в активные со всеми бюджетами и операциями. Если у пользователя есть активный карман с тем же именем без учёта регистра и краевых пробелов, восстановление MUST NOT выполняться, и интерфейс MUST показывать понятное сообщение о конфликте имени. Без явного выбора пользователя виджет MUST открывать первый активный карман; архивированный карман открывается по умолчанию только если активных карманов нет. Карман, который ещё сохраняется, MUST NOT выбираться по умолчанию; его чип MUST показываться с пометкой «сохраняется…» и MUST NOT реагировать на нажатия. Новый карман MUST становиться выбранным, как только сервер сохранил его, и до этого MUST NOT отправляться запросы по его временному id. Данные карманов MUST быть доступны только владельцу.

#### Scenario: Create and rename a pocket

- **WHEN** пользователь создаёт карман с именем или переименовывает собственный активный карман
- **THEN** изменённый список карманов сохраняется и доступен после повторной загрузки
- **AND** ранее созданные месячные бюджеты и операции остаются связанными с тем же карманом

#### Scenario: Archive a pocket

- **GIVEN** карман содержит месячные бюджеты или операции
- **WHEN** пользователь архивирует карман
- **THEN** карман, его бюджеты и операции остаются доступны в помесячной истории только для просмотра
- **AND** поле бюджета недоступно для изменения, а у операций нет действий изменения суммы и удаления

#### Scenario: Show archived pocket operations read-only in the expense journal

- **GIVEN** операция журнала расходов относится к архивированному карману
- **WHEN** пользователь видит её карточку в журнале или в истории кармана
- **THEN** у карточки нет действий изменения суммы и удаления
- **AND** карточка показывает подсказку «Карман в архиве — восстановите, чтобы изменить»
- **AND** система запрещает добавлять к архивному карману операции и создавать для него новые месячные бюджеты

#### Scenario: Reject changes to an archived pocket on the server

- **GIVEN** карман архивирован
- **WHEN** клиент напрямую вызывает изменение его месячного бюджета, изменение суммы или удаление его операции
- **THEN** изменение отклоняется, и сохранённые бюджет и операции не меняются

#### Scenario: Restore an archived pocket

- **GIVEN** карман архивирован, и среди активных карманов нет кармана с тем же именем
- **WHEN** пользователь выбирает «Восстановить»
- **THEN** карман снова становится активным с прежними бюджетами и операциями
- **AND** для него снова доступны изменение бюджета, новые операции, переименование и архивирование

#### Scenario: Refuse a restore that conflicts with an active name

- **GIVEN** карман «Подарки» архивирован, а активный карман называется « подарки »
- **WHEN** пользователь выбирает «Восстановить» для архивированного кармана
- **THEN** карман остаётся архивированным
- **AND** интерфейс сообщает, что активный карман с таким именем уже существует

#### Scenario: Open an active pocket by default

- **GIVEN** у пользователя есть архивированный и активный карманы, и архивированный создан раньше
- **WHEN** пользователь открывает или перезагружает dashboard без явного выбора кармана
- **THEN** выбран первый активный карман, а не архивированный

#### Scenario: Isolate pockets between users

- **GIVEN** карман принадлежит другому пользователю
- **WHEN** текущий пользователь пытается получить его данные или изменить карман, бюджет либо операцию
- **THEN** данные не выдаются и изменение не выполняется

#### Scenario: Select a new pocket after it is saved

- **GIVEN** у пользователя нет активных карманов
- **WHEN** пользователь создаёт карман «Отпуск»
- **THEN** пока карман сохраняется, его чип показан «Отпуск · сохраняется…» и не нажимается, а по нему не уходит ни одного запроса
- **AND** после сохранения выбран «Отпуск», и сервер не отвечает ошибкой 5xx
