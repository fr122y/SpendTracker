# Spec Delta

## MODIFIED Requirements

### Requirement: Manage personal pockets and preserve archived history

Система MUST предоставлять каждому пользователю отдельный список постоянных именованных карманов. Пользователь MUST иметь возможность создать карман, изменить его имя, архивировать его и восстановить архивированный карман. Архивирование MUST сохранять имя, бюджеты и операции только для просмотра: для архивированного кармана система MUST отклонять изменение месячного бюджета, создание месячных бюджетов, добавление покупок и переводов, изменение и удаление существующих операций, в том числе при прямом вызове серверного действия. Восстановление MUST возвращать карман в активные со всеми бюджетами и операциями. Если у пользователя есть активный карман с тем же именем без учёта регистра и краевых пробелов, восстановление MUST NOT выполняться, и интерфейс MUST показывать понятное сообщение о конфликте имени. Без явного выбора пользователя виджет MUST открывать первый активный карман; архивированный карман открывается по умолчанию только если активных карманов нет. Данные карманов MUST быть доступны только владельцу.

#### Scenario: Create and rename a pocket

- **WHEN** пользователь создаёт карман с именем или переименовывает собственный активный карман
- **THEN** изменённый список карманов сохраняется и доступен после повторной загрузки
- **AND** ранее созданные месячные бюджеты и операции остаются связанными с тем же карманом

#### Scenario: Archive a pocket

- **GIVEN** карман содержит месячные бюджеты или операции
- **WHEN** пользователь архивирует карман
- **THEN** карман, его бюджеты и операции остаются доступны в помесячной истории только для просмотра
- **AND** поле бюджета недоступно для изменения, а у операций нет действий изменения суммы и удаления

#### Scenario: Show archived pocket operations read-only in the expense journal

- **GIVEN** операция журнала расходов относится к архивированному карману
- **WHEN** пользователь видит её карточку в журнале или в истории кармана
- **THEN** у карточки нет действий изменения суммы и удаления
- **AND** карточка показывает подсказку «Карман в архиве — восстановите, чтобы изменить»
- **AND** система запрещает добавлять к архивному карману операции и создавать для него новые месячные бюджеты

#### Scenario: Reject changes to an archived pocket on the server

- **GIVEN** карман архивирован
- **WHEN** клиент напрямую вызывает изменение его месячного бюджета, изменение суммы или удаление его операции
- **THEN** изменение отклоняется, и сохранённые бюджет и операции не меняются

#### Scenario: Restore an archived pocket

- **GIVEN** карман архивирован, и среди активных карманов нет кармана с тем же именем
- **WHEN** пользователь выбирает «Восстановить»
- **THEN** карман снова становится активным с прежними бюджетами и операциями
- **AND** для него снова доступны изменение бюджета, новые операции, переименование и архивирование

#### Scenario: Refuse a restore that conflicts with an active name

- **GIVEN** карман «Подарки» архивирован, а активный карман называется « подарки »
- **WHEN** пользователь выбирает «Восстановить» для архивированного кармана
- **THEN** карман остаётся архивированным
- **AND** интерфейс сообщает, что активный карман с таким именем уже существует

#### Scenario: Open an active pocket by default

- **GIVEN** у пользователя есть архивированный и активный карманы, и архивированный создан раньше
- **WHEN** пользователь открывает или перезагружает dashboard без явного выбора кармана
- **THEN** выбран первый активный карман, а не архивированный

#### Scenario: Isolate pockets between users

- **GIVEN** карман принадлежит другому пользователю
- **WHEN** текущий пользователь пытается получить его данные или изменить карман, бюджет либо операцию
- **THEN** данные не выдаются и изменение не выполняется

### Requirement: Show and edit pocket history in the shared month context

Виджет карманов MUST использовать только общий выбранный dashboard date для месяца и MUST NOT предоставлять собственный календарь или выбор месяца. Виджет MUST показывать для выбранного месяца бюджет, использованную сумму и остаток, а также отдельную разбивку покупок и переводов. Активация разбивки MUST открывать историю соответствующего типа за этот месяц в одной карточке операции. Карточка MUST показывать комментарий, дату и категорию компактно; только сумма MUST редактироваться через явное действие. Для активного кармана пользователь MUST иметь возможность изменять месячный бюджет и суммы существующих покупок и переводов; эти изменения MUST пересчитывать месячные суммы и недельное покрытие. Интерфейс MUST предоставлять добавление покупки или перевода и создавать новый карман. Пользователь MUST иметь возможность удалить покупку или перевод активного кармана из истории через подтверждаемое действие; история архивированного кармана MUST быть доступна только для просмотра. Удаление MUST пересчитывать использованную сумму, остаток кармана и недельное покрытие, если удалён перевод. Форма новой операции MUST NOT содержать поле даты; новая операция MUST сохраняться с выбранной dashboard date, действующей в момент сохранения. Для покупки форма MUST использовать локальные keyword-based category suggestions обычного журнала: найденная категория показывается компактно, неизвестная подсказка открывает ручной выбор, а ручное переопределение сохраняется для будущего совпадающего описания.

#### Scenario: Follow the dashboard month

- **GIVEN** виджет карманов показан рядом с другими виджетами dashboard
- **WHEN** пользователь меняет дату через общий month picker dashboard
- **THEN** виджет показывает бюджеты и операции нового календарного месяца
- **AND** виджет не отображает свой отдельный выбор месяца или даты

#### Scenario: Open monthly history in one operation card

- **GIVEN** выбранный месяц содержит покупки и переводы кармана
- **WHEN** пользователь активирует одну из двух строк разбивки
- **THEN** открывается список только соответствующего типа операций за выбранный месяц, по одной карточке на операцию
- **AND** пользователь может изменить бюджет периода и сумму операции
- **AND** дата, комментарий и категория остаются видимыми без дополнительных редакторов
- **AND** сохранённые изменения пересчитывают used, remaining и недельное покрытие

#### Scenario: Add an operation on the selected date

- **GIVEN** активный карман открыт в виджете
- **WHEN** пользователь выбирает добавление покупки или перевода и заполняет обязательные поля
- **THEN** форма не показывает поле даты
- **AND** новая операция записывается с выбранной dashboard date
- **AND** если dashboard date изменена при открытой форме, операция записывается с новой датой
- **AND** покупка требует категорию, а перевод не требует категорию

#### Scenario: Delete an operation from pocket history

- **GIVEN** выбранный месяц содержит покупку или перевод активного кармана
- **WHEN** пользователь выбирает удаление и подтверждает его
- **THEN** операция исчезает из помесячной истории
- **AND** использованная сумма и остаток кармана пересчитываются
- **AND** недельное покрытие пересчитывается, если удалён перевод
- **AND** отмена подтверждения сохраняет операцию

#### Scenario: Suggest or manually override a purchase category

- **GIVEN** пользователь вводит описание новой покупки из кармана
- **WHEN** описание совпадает с сохранённым keyword mapping
- **THEN** категория показывается как выбранная подсказка без постоянно открытого списка
- **AND** пользователь может явно открыть ручной выбор и заменить подсказку
- **AND** если совпадения нет, ручной выбор категории становится доступен
- **AND** ручной выбор сохраняется как keyword mapping для будущих описаний
