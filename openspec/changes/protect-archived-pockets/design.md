# Design

## Context

Архив кармана хранится в `pockets.archived_at`. Помощник `assertCanUsePocket` уже отклоняет архивный карман для новых операций и инициализации месяца, но `setPocketMonthBudget` и изменение или удаление операций проверяли только владельца.

## Decisions

- Проверку архива выполняет сервер через существующий `assertCanUsePocket`; интерфейс только отражает её. Так прямой вызов Server Action тоже отклоняется.
- `restorePocket` возвращает результат `{ status: 'restored' } | { status: 'name_conflict' }`, а не бросает ошибку при конфликте: в production Next.js скрывает текст ошибок Server Actions, и клиент не смог бы отличить конфликт от сбоя. Клиентский хук превращает конфликт в `PocketNameConflictError`, чтобы сработал откат оптимистичного обновления, и не показывает общий toast отката для конфликта.
- Конфликт имени сравнивает имена после `trim()` и `toLocaleLowerCase('ru-RU')` только с активными карманами пользователя. Ограничения в базе нет (решение T-037), поэтому проверка и обновление не атомарны; гонка двух одновременных действий допускается.
- Выбор по умолчанию: явный выбор пользователя, иначе первый активный карман в порядке списка, иначе первый карман.

## Risks

- Операции архивного кармана в обычном журнале расходов по-прежнему показывают действия изменения и удаления; сервер их отклоняет, и оптимистичное изменение откатывается.
