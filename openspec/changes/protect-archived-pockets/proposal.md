# Proposal

## Why

Прожарка приложения 2026-10-15 (задача T-038) нашла три дефекта архива карманов. Бюджет архивного кармана редактируется, и сервер сохраняет изменение (5000 → 5500): `setPocketMonthBudget` проверяет только владельца кармана, но не архив. Вернуть карман из архива нельзя ни в интерфейсе, ни в коде. После перезагрузки по умолчанию выбран первый карман списка, даже если он архивный.

Владелец решил (2026-10-15): архивный карман только для просмотра, сервер отклоняет любое изменение его бюджета и операций; восстановление возвращает карман в активные; по умолчанию выбирается первый активный карман.

## What Changes

- Server Actions `setPocketMonthBudget`, `updateExpense` и `deleteExpense` отклоняют изменение бюджета и операций архивированного кармана.
- В виджете «Карманы» поле бюджета архивного кармана недоступно, у операций его истории нет действий изменения суммы и удаления.
- Новый Server Action `restorePocket` и действие «Восстановить» в виджете возвращают карман в активные. Если активный карман с тем же именем (без учёта регистра и краевых пробелов) существует, карман не восстанавливается, а интерфейс показывает сообщение о конфликте.
- Без явного выбора виджет открывает первый активный карман.

Критерии приёмки: прямой вызов изменения бюджета или операции архивного кармана отклоняется; кнопка «Восстановить» делает карман активным; при конфликте имени показано понятное сообщение; после перезагрузки выбран активный карман.

Вне объёма:

- Миграции и ограничения базы данных: уникальность имени остаётся на уровне приложения (T-037).
- Скрытие архивных карманов за переключателем (опциональный пункт T-038).
- Действия изменения и удаления в карточках обычного журнала расходов: сервер отклоняет их для архивного кармана, оптимистичное изменение откатывается с общим уведомлением.

Зависимости: нет.

Риски: операцию архивного кармана больше нельзя исправить или удалить без восстановления кармана; это намеренное изменение прежнего требования.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `pockets`: требования «Manage personal pockets and preserve archived history» и «Show and edit pocket history in the shared month context» — архив только для просмотра, восстановление, выбор активного кармана по умолчанию.

## Impact

- `src/shared/api/pocket-actions.ts`, `src/shared/api/expense-actions.ts`, `src/shared/api/index.ts`.
- `src/entities/pocket` (`useRestorePocket`, `PocketNameConflictError`), `src/entities/expense/ui/expense-card.tsx` (`onDelete` необязателен).
- `src/widgets/pockets`.
- Тесты в `__tests__` этих слайсов и e2e `e2e/pockets.spec.ts`. Схема базы данных не меняется.
