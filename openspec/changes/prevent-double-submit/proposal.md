# Proposal

## Why

Прожарка приложения 2026-10-15 (задача T-037) нашла дубли от повторных кликов и неразличимые карманы. Двойной клик «Создать карман» создаёт два кармана «Дабл ТЕСТ»: защита `isPending` в форме читает значение прошлого рендера. Три быстрых клика «Добавить» в журнале создают три одинаковых расхода. Карман можно создать с именем уже существующего активного кармана, и в выпадающем списке их не различить. «Добавить категорию» в калькуляторе накоплений сразу сохраняет строку с пустым именем.

Владелец решил (2026-10-15): имена активных карманов уникальны без учёта регистра и краевых пробелов, проверка в приложении и Server Action; частичный уникальный индекс в базе — отдельная задача T-058; защита от двойного клика — замок через ref; idempotency расхода — без новых колонок, если возможно; в этом раунде без миграций.

## What Changes

- Формы создания кармана, переименования кармана, расхода в журнале, покупки и перевода кармана, расхода проекта, проекта, личной и общей категории отправляют запрос один раз, сколько бы раз подряд ни сработала отправка, пока предыдущая не завершилась.
- `createPocket` и `renamePocket` отклоняют имя другого активного кармана пользователя (после `trim`, без учёта регистра) и возвращают результат `name_conflict`, а не исключение; форма показывает «Карман с таким названием уже есть». Имя архивного кармана можно использовать. `createPocket`, `renamePocket` и `restorePocket` проверяют и записывают имя под блокировкой строки пользователя.
- `addExpense` принимает необязательный id операции, созданный клиентом. Повторный запрос с тем же id не создаёт вторую запись и возвращает успех. Журнал и формы операций кармана передают такой id; форма операции кармана сохраняет его между повторами после сбоя. Новых колонок не нужно: id — первичный ключ `expense`.
- «Добавить категорию» в распределении дохода добавляет строку только локально; она сохраняется после ввода имени, а удаление безымянной строки ничего не сохраняет.

Критерии приёмки: двойной и тройной клик «Создать карман» создают один карман; быстрые повторные клики при добавлении расхода создают один расход на сервере; создание и переименование в имя активного кармана отклоняются в форме и в Server Action; «Добавить категорию» не сохраняет строку, пока не введено имя.

Вне объёма:

- Уникальный индекс имён активных карманов и любые миграции базы — T-058.
- Idempotency-ключ для действий, кроме создания расхода: карман, проект и категория защищены только замком формы.

Зависимости: T-038 (проверка конфликта имени при восстановлении) уже в `main`; её сравнение имён вынесено в общий помощник.

Риски: без ограничения в базе запись в обход этих Server Actions всё ещё может создать дубль активного имени (до T-058). Блокировка строки пользователя коротко сериализует операции с именами карманов одного пользователя.

## Capabilities

### New Capabilities

- `form-submission`: однократная отправка форм создания и idempotency создания операции.

### Modified Capabilities

- `pockets`: новое требование об уникальности имён активных карманов.
- `income-allocation`: новое требование о сохранении добавленной категории только с именем.
