# projects Specification

## Purpose

Проекты учитывают деньги, взятые из проекта и возвращённые в него, и не дают вернуть больше, чем находится «На руках».

## Requirements

### Requirement: Keep project returns within cash on hand

«На руках» проекта MUST равняться сумме операций «Взял из проекта» минус сумма операций «Вернул в проект» этого проекта; проектные расходы её не меняют. Система MUST отклонять добавление, изменение или удаление операции взятия или возврата, после которого «На руках» проекта стала бы отрицательной, в том числе при прямом вызове серверного действия. Серверная проверка MUST выполняться в транзакции с блокировкой строки проекта. Формы журнала и проекта MUST показывать понятную ошибку на русском и не отправлять возврат больше «На руках».

#### Scenario: Reject a return above cash on hand in the form

- **GIVEN** из проекта взято 5000 ₽, возвратов нет
- **WHEN** пользователь вводит возврат 7000 ₽
- **THEN** форма показывает «Нельзя вернуть больше, чем на руках: 5 000 ₽»
- **AND** кнопка «Добавить» недоступна

#### Scenario: Reject a return above cash on hand on the server

- **GIVEN** «На руках» проекта 4000 ₽
- **WHEN** клиент напрямую добавляет возврат 4001 ₽ или увеличивает сумму существующего возврата сверх «На руках»
- **THEN** операция отклоняется, и сохранённые операции не меняются

#### Scenario: Reject deleting a withdrawal that leaves cash on hand negative

- **GIVEN** из проекта взято 5000 ₽ и возвращено 3000 ₽
- **WHEN** пользователь удаляет операцию «Взял из проекта» на 5000 ₽
- **THEN** сервер отклоняет удаление, и операция остаётся в списке
- **AND** интерфейс показывает «Нельзя удалить: на руках станет меньше 0 — сначала удалите возврат»

#### Scenario: Accept a return of the whole cash on hand

- **GIVEN** «На руках» проекта 4000 ₽
- **WHEN** пользователь возвращает 4000 ₽
- **THEN** возврат сохраняется, и «На руках» становится 0 ₽

### Requirement: Guide the user to projects before project operations

Журнал расходов MUST предлагать сценарии «Проектный расход», «Взял из проекта» и «Вернул в проект» только если у пользователя есть проект. Без проектов журнал MUST показывать подсказку о создании проекта в разделе «Проекты». Форма создания проекта MUST закрываться после успешной отправки.

#### Scenario: Journal without projects

- **GIVEN** у пользователя нет проектов
- **WHEN** пользователь открывает журнал расходов
- **THEN** список сценариев не содержит проектных операций
- **AND** журнал показывает подсказку «Проектные операции появятся после создания проекта в разделе «Проекты».»

#### Scenario: Close the create-project form

- **WHEN** пользователь создаёт проект
- **THEN** форма создания закрывается, и снова видна кнопка «Создать проект»
